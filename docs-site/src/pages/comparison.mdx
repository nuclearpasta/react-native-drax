# React Native drag and drop libraries compared

The react-native-drax maintainers at NuclearPasta maintain this page, so we have a stake in one of the five libraries compared here. To make the comparison checkable, every cell in the matrix links to its source. All data is as of 30 Oct 2026. If you find a mistake, please [open a GitHub issue](https://github.com/nuclearpasta/react-native-drax/issues).

## Quick answer: which library fits which job

Each recommendation below comes only from the [feature matrix](#feature-matrix). If another library fits a job better than react-native-drax, the table names it.

| Job | Libraries that fit | Why (from the matrix) |
|---|---|---|
| Simple reorderable list | react-native-reorderable-list, react-native-draggable-flatlist, react-native-drax, react-native-reanimated-dnd | All four document a sortable vertical list. reorderable-list and draggable-flatlist are FlatList-based list components with a drop indicator or placeholder. For drax, see [sortable list in React Native](https://nuclearpasta.com/react-native-drax/guides/sortable-list). |
| Sortable grid | react-native-sortables, react-native-drax, react-native-reanimated-dnd | sortables has `Sortable.Grid`. drax has `numColumns` and a mixed-size grid ([sortable grid guide](https://nuclearpasta.com/react-native-drax/guides/sortable-grid), [mixed-size grid example](https://nuclearpasta.com/react-native-drax/examples/mixed-grid)). reanimated-dnd documents grids with insert and swap. reorderable-list says it doesn't support multi-column lists. |
| Flex / wrapping layout | react-native-sortables | sortables is the only library here that documents a flex (wrapping) layout (`Sortable.Flex`). drax doesn't support it. |
| Free-form drop zones | react-native-drax, react-native-reanimated-dnd | Both document draggable and droppable primitives, and both document center / intersect / contain collision modes. drax also documents drop acceptance and capacity ([drop zone acceptance](https://nuclearpasta.com/react-native-drax/guides/drop-zone-acceptance)). |
| Moving items between lists | None documents it as stable | In drax, cross-container drag is Experimental ([drag between lists (experimental)](https://nuclearpasta.com/react-native-drax/guides/cross-container-drag)). reanimated-dnd tracks items across multiple drop zones, but cross-list sorting is unverified. draggable-flatlist and reorderable-list document nested lists, not moving items between them. Prototype this before you commit to a library. |
| Web support | react-native-drax | drax is the only library here that documents web support ([web support](https://nuclearpasta.com/react-native-drax/guides/web-support)). The sortables repo has a web example app, but its level of web support is unverified. reanimated-dnd and reorderable-list don't claim web support. |
| FlashList / LegendList | react-native-drax | drax documents support for any list component, naming FlatList, FlashList and LegendList [R-drax] ([DraxList API](https://nuclearpasta.com/react-native-drax/api/components/drax-list)). |

## Feature matrix

How to read the cells:

- **Yes / No:** the cited source says so explicitly.
- **Not documented** (or **Not stated**): the cited source doesn't mention the feature. That isn't the same as "No". The feature may exist and just not be documented.
- **unverified:** we couldn't confirm the cell from a source. Don't rely on it until it's checked.
- **n/a:** the criterion doesn't apply to that kind of library. For example, a list component has no free-form drop-acceptance setting.

Column abbreviations: **draggable-flatlist** = react-native-draggable-flatlist, **reanimated-dnd** = react-native-reanimated-dnd, **sortables** = react-native-sortables, **reorderable-list** = react-native-reorderable-list.

What these signals tell you, and what they don't:

- **Downloads** show how widely a package is installed. They don't measure quality or fit for your use case. Automated installs (CI, for example) count too.
- **Stars** show interest at some point in time, not current activity.
- **Open issues + PRs** comes from GitHub's `open_issues_count`, which counts open pull requests as well as issues. A high number can mean heavy use, a slow triage process, or both. A low number doesn't guarantee few bugs.
- **Last push** shows recent repository activity. A push isn't a release, so read it alongside the latest version date.

## Library profiles

### react-native-drax

**What it's for:** free-form drag-and-drop (draggable views and drop zones) plus sortable lists and grids, in one library.

**Where it's strongest:** drop zones with center / intersect / contain collision modes and `acceptsDrag` + `capacity`. Sortable lists that work on any list component (FlatList, FlashList, LegendList). Grids with `numColumns` and mixed item sizes. Documented web support. Auto-generated accessibility labels and reduced-motion handling on sortable list items. For the design behind it, see [how Drax stays at 60fps](https://nuclearpasta.com/react-native-drax/guides/performance).

**Limits:** moving items between lists is Experimental. There's no flex (wrapping) layout and no haptic feedback. Because drax depends on Reanimated 4, it runs only on the New Architecture.

**Requirements:** Reanimated ^4.0.0, Gesture Handler >=2.0.0 (v3 recommended) and React Native 0.78 (required by Reanimated 4). Version 1.0.0 was a full rewrite, released 2026-03-22, and 1.1.0 followed on 2026-03-23. Docs for the unreleased 2.x line are at [next](https://nuclearpasta.com/react-native-drax/next/getting-started); planned features are listed in the [roadmap](https://nuclearpasta.com/react-native-drax/guides/roadmap).

**Links:** [react-native-drax docs](https://nuclearpasta.com/react-native-drax) · [GitHub](https://github.com/nuclearpasta/react-native-drax) · [npm](https://www.npmjs.com/package/react-native-drax)

### react-native-draggable-flatlist

**What it's for:** a drag-to-reorder FlatList.

**Where it's strongest:** it's the most-downloaded library in this comparison, with 1,943,449 npm downloads from 2026-09-29 to 2026-10-28. Its README documents handles via a `drag()` callback, auto-scroll (`autoscrollThreshold`, `autoscrollSpeed`), `renderPlaceholder`, and item entering and exiting animations.

**Limits:** grids, free-form drop zones and moving items between lists aren't documented. Architecture support isn't documented either, and New Architecture flicker issues [#602](https://github.com/computerjazz/react-native-draggable-flatlist/issues/602) and [#621](https://github.com/computerjazz/react-native-draggable-flatlist/issues/621) are open. The latest release is 4.0.3 (2025-05-06). On 30 Oct 2026, the repo had 232 open issues + PRs.

**Requirements:** Reanimated >=2.8.0, Gesture Handler >=2.0.0, React Native >=0.64.0.

**Links:** [README](https://github.com/computerjazz/react-native-draggable-flatlist) · [npm](https://www.npmjs.com/package/react-native-draggable-flatlist)

### react-native-reanimated-dnd

**What it's for:** free-form drag-and-drop (Draggable, Droppable) plus sortable lists and grids. It's the library closest to drax in scope.

**Where it's strongest:** grids with insert and swap, center / intersect / contain collision modes, "axis-locked and bounded dragging", variable-height lists, optional FlatList rendering with virtualization, and a dedicated accessibility guide (labels are set manually).

**Limits:** it doesn't claim web support ("designed specifically for mobile, not ported from web"). A drop indicator isn't documented, and cross-list sorting is unverified. Because it needs Reanimated 4, it runs on the New Architecture only.

**Requirements:** v2 needs Reanimated >=4.2.0, react-native-worklets >=0.7.0, Gesture Handler >=2.28.0 and React Native >=0.80.0. It's "tested against Expo SDK 55 and React Native 0.83". The latest release is 2.0.0 (2026-03-16).

**Links:** [docs](https://reanimated-dnd-docs.vercel.app/docs/intro) · [GitHub](https://github.com/entropyconquers/react-native-reanimated-dnd) · [npm](https://www.npmjs.com/package/react-native-reanimated-dnd)

### react-native-sortables

**What it's for:** sortable grid and flex layouts (`Sortable.Grid`, `Sortable.Flex`).

**Where it's strongest:** it's the only library in this comparison that documents a flex (wrapping) layout and optional haptic feedback. It supports both the Old and New Architecture, and its README says it's "Expo compatible". It also documents handles, a drop indicator, insertion and swapping, items with different dimensions, and add/remove layout animations.

**Limits:** the README lists only Grid and Flex layouts, so vertical and horizontal lists are unverified. Free-form drop zones and moving items between lists aren't documented. The repo has a web example app, but the level of web support is unverified.

**Requirements:** Reanimated >=3.0.0 (works with Reanimated 3 or 4), Gesture Handler >=2.0.0, React Native `*`. The latest release is 1.10.1 (2026-09-26).

**Links:** [docs](https://react-native-sortables-docs.vercel.app/) · [GitHub](https://github.com/MatiPl01/react-native-sortables) · [npm](https://www.npmjs.com/package/react-native-sortables)

### react-native-reorderable-list

**What it's for:** a FlatList-based reorderable list.

**Where it's strongest:** a built-in drop indicator (`renderDropIndicator`), nested lists, handles via the `useReorderableDrag` hook, `autoscroll*` props and layout animations. It supports vertical and horizontal lists.

**Limits:** `numColumns` isn't supported, so there are no grids. Moving items between lists isn't documented, and it doesn't claim web support (its badges list iOS and Android only). It's pre-1.0 (0.x), and its README says the API isn't stable yet. Its architecture support is unverified.

**Requirements:** Reanimated >=3.12.0, Gesture Handler >=2.12.0, React Native `*`. The latest release is 0.18.2 (2026-10-18).

**Links:** [README](https://github.com/omahili/react-native-reorderable-list) · [npm](https://www.npmjs.com/package/react-native-reorderable-list)

## Requirements at a glance (New Architecture, Reanimated, Expo)

The Reanimated version a library requires decides whether you can use it on the Old Architecture ([RA-compat]):

- **Reanimated 4 or later, New Architecture only:** react-native-drax (^4.0.0) and react-native-reanimated-dnd (>=4.2.0).
- **Reanimated 3 or later, which works on both architectures:** react-native-sortables (>=3.0.0; documents Old and New) and react-native-reorderable-list (>=3.12.0). react-native-draggable-flatlist's peer range starts lower (>=2.8.0), so it also accepts Reanimated 3. Except for sortables, these libraries don't document which architectures they support. Their peer ranges allow Reanimated 3, but that alone doesn't confirm they run on either architecture.

The deciding constraint is this: React Native 0.82+ and Expo SDK 55+ always run the New Architecture ([React Native 0.82 release notes](https://reactnative.dev/blog/2025/10/08/react-native-0.82), [Expo New Architecture guide](https://docs.expo.dev/guides/new-architecture/)). On those versions, the Old Architecture question doesn't come up. It only matters for apps still on older React Native versions that haven't migrated.

## How this comparison was made

**Conflict of interest:** the react-native-drax maintainers wrote this page, and we built one of the libraries it compares. To keep that in check, every cell cites a public source. Cells we couldn't confirm are marked "unverified" rather than filled in, and the quick-answer table recommends other libraries where the matrix shows they fit better.

**Sources:** each library's README and docs site, the npm registry API (versions, peer dependencies, types and release dates), the npm downloads API (window 2026-09-29 to 2026-10-28), and the GitHub API (stars, open issues + PRs, last push and license). For drax, a few cells come from the drax docs root table, which is self-reported.

**As of:** 30 Oct 2026. We refresh the data at least quarterly and update the dates on each block when we do.

**Report a correction:** if a cell is wrong or out of date, especially for a library you maintain, [open an issue on GitHub](https://github.com/nuclearpasta/react-native-drax/issues) and include a link to the source.
